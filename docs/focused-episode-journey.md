# 默认创作路径

主入口收拢为「开始一集 → 打磨内容 → 试听交付」。节目库、设置及素材专业工具保留为次级入口。

## 执行边界

- 开始一集必须提供主题或素材。听众与听后收获可选。
- 默认动作执行 fetch / preprocess / research / topic_selection / facts / script，保存后停在稿件。没有声音配置也可以写稿。
- 默认编辑器直接使用当前事实卡和稿件，不根据 UI 素材选择重建、清空事实卡。
- 确认内容后进入声音制作；制作、终审、导出是试听交付中的连续操作。
- 来源核验、稿件检查、发音预检、音频质量检查、绑定成片的人工终审保持原有规则。生成稿件不代表可发布。
- 新闻晨报专业编辑器仍保留；默认入口不再强求固定七条新闻。深度分析仍需证据研究，篇幅不能替代依据。

## 数据和消费者

不新增状态键、节点或 IPC。现有 `runtime_config.quick_brief` 记录 `requested_at`、`topic`、`material_text`，并记录可选的 `audience`、`takeaway`。它表示默认创作入口的意图，不是质量通过凭证。

- React 开始页写入意图；Electron 创建、持久化和 runner 继续传递当前 runtime_config。
- FactsNode 按实际事实卡选择本期内容；ScriptNode 根据选定事实数量计算篇幅，写作提示接收听众和收获，不改全局偏好。
- 编辑器使用已有 script / edited_script / facts；编辑继续失效下游音频及终审结果。
- 语音、审核、导出沿用当前 schema；发布格式使用统一 `episode_policy`：完整开场/收尾、1–20 个有事实关联的正文段、至多一个经过研究的深度段，不要求固定 6+1。音频审核核对实际计划的完整性、转场位置与实测时长，不再用固定节目长度代表质量。
- CLI 和离线晨报 demo 保留既有写作模板，也消费同一发布门禁。来源、模型事实核验、编辑质量、发音、实测音质和绑定成片的人工终审不因格式自由而省略。
- 默认流程停在 script 是正常待审状态。只有实际尝试声音制作后未得到音频，才报告缺失音频。

验证重点：没有 TTS 也能成稿、无输入禁用、稿件停止与恢复、事实不被 UI 清空、编辑失效下游、稀疏素材不凑条数、失败保持真实原因、终审前不能正式导出。
